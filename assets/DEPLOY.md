# Как выложить сайт в интернет (бесплатно)

Сайт — чистая статика (HTML + CSS + JS + фото), поэтому подойдёт любой бесплатный хостинг.
Хостинг сам будет пересобирать сайт при каждом `git push` — обновлять его потом можно в один коммит.

---

## 1. Render — то, что ты хотел

**Итог:** сайт по адресу `https://love-site-xxxx.onrender.com`, свой домен подключается бесплатно.

### Шаг 0. Залить файлы на GitHub

`render.yaml` и папку `love_site` (вместе с `styles.css`, `script.js`, `img/`) нужно закоммитить в
репозиторий `darknesshefake-code/assets` в ветку `main`. Файлы из этой папки уже подготовлены —
просто распакуй архив `love_site_deploy_pack.zip` в клон репозитория и сделай:

```bash
cd assets
git add -A
git commit -m "Красивый сайт: 4 страницы + конфиги деплоя"
git push
```

### Шаг 1. Аккаунт Render

1. Открыть <https://render.com> → **Get Started** → **GitHub**.
2. Разрешить доступ к репозиториям (**карта не нужна**, план Hobby бесплатный).

### Шаг 2. Создать сайт

Вариант **А — через готовый `render.yaml` (быстрее):**

1. Дашборд → **New +** → **Blueprint**.
2. Выбрать репозиторий `darknesshefake-code/assets` → **Connect**.
3. Render сам прочитает `render.yaml` и создаст сайт `love-site`. Нажать **Apply**.

Вариант **Б — вручную:**

1. Дашборд → **New +** → **Static Site**.
2. Выбрать репозиторий `darknesshefake-code/assets` → **Connect**.
3. Заполнить:
   - **Name:** `love-site`
   - **Branch:** `main`
   - **Build Command:** *оставить пустым* (собирать нечего)
   - **Publish Directory:** `love_site` ← это важно, сам сайт лежит в подпапке
4. Нажать **Create Static Site**.

Через ~30 секунд сайт живой: ссылка вида `https://love-site-xxxx.onrender.com`, HTTPS уже включён.

### Шаг 3. Обновления в будущем

- Правишь файлы → `git commit` → `git push` в `main` → Render пересобирает сайт сам (≈30 сек).
- Руками: **Manual Deploy** → **Deploy latest commit**.
- Если правишь `love_site_one_file.html` — не забудь `python3 build_one_file.py`, чтобы он пересобрался из страниц.
- **Лайфхак:** можно править прямо в браузере — в репозитории на GitHub нажать клавишу `.`
  (откроется редактор github.dev), поправить текст, закоммитить в `main` — сайт обновится сам.

### Лимиты бесплатного плана Render

| Что | Сколько |
|-----|---------|
| Статические сайты | неограниченно |
| Трафик | 100 ГБ/мес на сайт (наш сайт ~2,5 МБ → это десятки тысяч открытий) |
| Свой домен | 2 домена на Hobby-плане, SSL бесплатно и автоматически |
| Сборка | 500 минут/мес общих |
| Засыпание | **статические сайты не засыпают** (спят только web-сервисы) |

> Трафик считается и по `/photos/` тоже: оригиналы фото (4,6 МБ) лежат в публикуемой папке.
> Если не хочешь их выкладывать — перенеси папку `photos/` из `love_site/` в корень репозитория,
> сайт от этого не сломается (он использует `img/`).

## 1.1. Если сборка упала с ошибкой Docker

**Симптом в логах Render:**

```
Cloning from https://github.com/.../assets
Checking out commit ... in branch main
#1 [internal] load build definition from Dockerfile
error: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory
error: exit status 1
```

**Что это значит:** создан **Web Service** (его Render по умолчанию собирает как Docker-образ), а не
**Static Site**. Нашему сайту вообще не нужна сборка: это готовые HTML/CSS/JS/фото.
`Dockerfile` в репозитории нет и не должно быть — это не ошибка в файлах, а неверный тип сервиса.

**Как исправить:**

1. Render → открыть упавший сервис → **Settings** → внизу **Delete Service** → подтвердить.
   (Тип сервиса после создания не меняется, поэтому именно удаляем.)
2. Дашборд → **New +** → выбрать **Static Site** (не Web Service!).
3. Репозиторий `darknesshefake-code/assets` → **Connect**.
4. Заполнить поля:
   - **Name:** `love-site`
   - **Branch:** `main`
   - **Root Directory:** *оставить пустым*
   - **Build Command:** *оставить пустым полностью* ← ключевой момент
   - **Publish Directory:** `love_site` ← вторая ключевая строка
5. **Create Static Site** → через ~30 секунд сайт откроется по адресу `https://love-site-xxxx.onrender.com`.

Если **Publish Directory** указать пустым или `./`, Render опубликует корень репозитория, где нет
`index.html` — получишь страницу «Not Found». Папку с сайтом указывать обязательно.

## 1.1.1. Как выглядит правильная структура на Render

После всех шагов в дашборде должно быть **два** сервиса:

| Сервис | Тип | Root Directory | Publish Directory | Адрес | За что отвечает |
|--------|-----|----------------|-------------------|-------|-----------------|
| `i-love-you-anya-site` | **Static Site** | пусто | `love_site` | `https://<имя>.onrender.com` | сам сайт со всеми страницами |
| `i-love-you-anya` | **Web Service** (Python) | `stats_service` | — | `https://i-love-you-anya.onrender.com` | цифры для страницы «Статистика» |

Если открыть адрес **сайта** и дописать `/stats.json` — увидишь выгрузку,
если открыть адрес **сервиса** и дописать `/api/stats` — увидишь JSON с числами.
Не наоборот: это два разных сервиса с двумя разными адресами.

## 1.2. Сервис статистики переписки (второй сервис на Render)

Страница «Наша переписка в цифрах» берёт числа у отдельного сервиса: статический сайт не умеет
запускать Python и держать сессию Telegram, поэтому счётчик живёт рядом — в папке `stats_service/`.

### Шаг 1. Свои ключи Telegram

1. Зайти на <https://my.telegram.org> → **API development tools** → создать приложение.
2. Записать **api_id** и **api_hash**.

> ⚠️ **Важно.** Пара `api_id` + `api_hash` вместе с `TG_SESSION` — это полный доступ к твоему
> аккаунту Telegram. Их нельзя публиковать, коммитить в GitHub или присылать в чатах.
> Если ключи уже где-то засветились — удали приложение на my.telegram.org
> (**Delete application**) и создай новое, а старые сессии заверши в Telegram →
> Настройки → Устройства → завершить.

### Шаг 2. Сгенерировать TG_SESSION (один раз, на компьютере)

```bash
cd stats_service
pip install telethon
python make_session.py
```

Скрипт спросит номер телефона и код из Telegram, а затем напечатает длинную строку —
это `TG_SESSION`. Она же сохранится в локальный `.env` (в git он не попадёт — он в `.gitignore`).

### Шаг 3. Создать сервис на Render

**Вариант А — через Blueprint:** если в репозитории есть `render.yaml`, то **New + → Blueprint →
выбрать репозиторий → Apply** — Render создаст сразу и сайт, и сервис статистики, попросив
значения `API_ID`, `API_HASH`, `TG_SESSION`.

**Вариант Б — вручную:** **New + → Web Service** → выбрать репозиторий, и указать:

| Поле | Значение |
|------|----------|
| Name | `love-stats-api` |
| Language / Runtime | **Python 3** |
| Root Directory | `stats_service` ← обязательно |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/health` |
| Instance Type | **Free** |

Затем в **Environment** добавить переменные:

| Переменная | Значение |
|-----------|----------|
| `API_ID` | число с my.telegram.org |
| `API_HASH` | строка с my.telegram.org |
| `TG_SESSION` | строка из `make_session.py` **или** пусто, если войдёшь через `/login` |
| `LOGIN_SECRET` | любое секретное слово — включает страницу входа `/login` |
| `TARGET_PHONE` | `+380669543625` |
| `TARGET_NAME` | как подписать её на сайте (необязательно) |
| `TARGET_USERNAME` | `@username` вместо номера, если номер не находится (необязательно) |
| `MY_NAME` | `Я` (необязательно) |
| `ALLOWED_ORIGINS` | `*` или адрес сайта (можно ограничить) |
| `TRIGGER_WORD` | `инфо` — слово, на которое сервис отвечает цифрами в чате (необязательно) |

> Здесь тип сервиса — именно **Web Service**, а не Static Site: нужен работающий Python-процесс.
> Ошибка `error: failed to read dockerfile` бывает, когда выбран Docker-рантайм вместо Python 3.

### Шаг 4. Подключить сайт к сервису

1. Открыть адрес сервиса + `/api/stats` — должен вернуться JSON с числами
   (первый ответ может прийти через 30–60 секунд: бесплатный сервис просыпается).
2. Скопировать адрес вида `https://love-stats-api.onrender.com`
   (если назвать сервис ровно `love-stats-api`, адрес совпадёт с уже прописанным в `script.js` —
   и править код вообще не придётся).
3. Вставить его в `love_site/script.js` в самую первую строку блока статистики:

   ```js
   var STATS_API_DEFAULT = 'https://love-stats-api.onrender.com';
   ```

4. `git push` → сайт пересоберётся, страница «Статистика» покажет цифры.

### Что нужно знать про бесплатный план

- Сервис **засыпает после 15 минут** без запросов и просыпается при первом заходе (до минуты).
  Страница это учитывает: показывает «сервер просыпается…» и сама догружает цифры.
- Тратится 750 часов/месяц общего времени инстансов: одного сервиса 24/7 ровно хватает.
  Если хочется, чтобы он не спал, — бесплатный мониторинг вроде UptimeRobot, который раз в
  10 минут дергает `/api/health`, решает вопрос.
- Счётчики хранятся в SQLite-файле рядом с кодом. При пересборке сервиса файл теряется,
  но ничего не ломается: сервис при старте заново пересчитает историю чата (это займёт
  несколько секунд-минут, сайт покажет «считаю историю…»).
- Если Telegram ответит `FloodWait`, сервис подождёт и продолжит — данные не потеряются.
- Триггер из исходного скрипта тоже работает: напиши в этом чате слово `инфо` — сообщение
  заменится той же статистикой (слово меняется переменной `TRIGGER_WORD`).

## 1.3. Разбор: «сайт пустой», а по адресу JSON

**Что произошло на самом деле.** Тот адрес, который открывается (`i-love-you-anya.onrender.com`) —
это **не сайт, а бэкенд статистики**. Он создан как Web Service с Root Directory `stats_service`,
поэтому Render запустил Python (uvicorn), и по корню отдаётся JSON вида:

```json
{"service":"статистика переписки","stats":"/api/stats","health":"/api/health","status":"error"}
```

`status: "error"` здесь значит ровно одно: **не заданы `API_ID`, `API_HASH`, `TG_SESSION`**.
Раньше это не ломало и не могло сломать сам сайт — сервис статистики отвечает только за цифры
на одной странице.

**Чего не хватает:** отдельного **Static Site** для самого сайта. Это второй сервис, у него
свой адрес. Создаём:

| Поле | Значение |
|------|----------|
| Тип | **New + → Static Site** (не Web Service!) |
| Repository | `darknesshefake-code/assets` |
| Name | `i-love-you-anya-site` (любое) |
| Branch | `main` |
| **Root Directory** | **пусто** ← не `stats_service`! |
| Build Command | **пусто** |
| **Publish Directory** | **`love_site`** |

После **Create Static Site** появится свой адрес вида `i-love-you-anya-site.onrender.com` —
вот он и есть сайт. Root Directory указывать не нужно: сайт лежит прямо в корне репозитория
в папке `love_site`.

> Быстрая проверка «site или не site»: открой `/index.html`. У статического сайта откроется
> страница «Я никогда не забуду твои подарки»; у Python-сервиса будет `{"detail":"Not Found"}`.

## 1.3.1. Ошибка `BotMethodInvalidError` — сессия от бота

**Симптом в логах Render:**

```
INFO авторизован как Love Anya Bot (@im_love_anya_bot)
INFO по номеру не нашлось (ValueError), перебираю диалоги…
ERROR ошибка подключения
telethon.errors.rpcerrorlist.BotMethodInvalidError: The API access for bot users is
restricted. The method you tried to invoke cannot be executed as a bot
(caused by GetDialogsRequest)
INFO  Application startup complete.  ← сервис жив, но цифр не будет
```

**Причина:** `TG_SESSION` сгенерирован для **бота** (вход по бот-токену от @BotFather),
а не для обычного аккаунта. Telegram в принципе запрещает ботам читать историю чатов и
список диалогов — и `GetDialogsRequest`, и `GetHistoryRequest` для них закрыты.
То есть бот физически не может посчитать вашу переписку.

**Исправление** — сгенерировать сессию своего аккаунта по номеру телефона:

1. Запустить `make_session.py` заново (любым способом из раздела 1.4).
2. Ввести **номер телефона** и код **из приложения Telegram**. Бот-токен не вставлять нигде.
3. Скрипт теперь сам проверяет, кто вошёл: если это бот — он скажет об этом и
   **не покажет строку сессии** (чтобы не вставлять бесполезную).
4. В Render → сервис статистики → Environment → заменить `TG_SESSION` на новую строку.

Проверить имеющуюся строку, ничего не меняя:

```bash
python make_session.py --check "строка_сессии"
```

Скрипт ответит, обычный это аккаунт или бот, и работает ли чтение диалогов.
Сервис тоже проверяет это при старте: если вошёл бот, в логе и в `/api/health` будет
понятное объяснение, а не загадочный трейсбек.

> Итог простыми словами: **для счётчика сообщений нужен userbot** — сессия твоего
> личного аккаунта. Бот не подходит никак, это ограничение Telegram, а не кода.

## 1.5. 🏆 Самый простой способ: вход в Telegram прямо в браузере (QR-код)

Ничего устанавливать не нужно, код подтверждения вводить не нужно. Вход делается один раз
на странице самого сервиса — кодом, который надо отсканировать телефоном.

**Подготовка (одну переменную добавить):**

1. Render → сервис статистики → **Environment** → **Add Environment Variable**:
   `LOGIN_SECRET` = любое секретное слово, например `anya-2026`.
2. **Save** — сервис перезапустится сам (10–30 секунд).

**Вход:**

3. Открой в браузере (подставь свой адрес сервиса и своё слово):

   ```
   https://i-love-you-anya.onrender.com/login?secret=anya-2026
   ```

4. Нажми **«Показать QR-код для сканирования»**. Если сервис спал — первый запрос может
   занять до минуты, страница подождёт и покажет код.
5. На телефоне: **Telegram → Настройки → Устройства → Подключить устройство** → наведи
   камеру на QR-код. Всё, вход выполнен — страница сама напишет «Готово!».
6. Обнови страницу сайта: цифры появятся (первый пересчёт истории может занять до минуты,
   на сайте будет видно «считаю историю…»).

**Чтобы вход не сбрасывался после пересборки сервиса:** после успешного входа страница
показывает строку сессии — скопируй её в переменную `TG_SESSION` (Render → Environment).
Так вход сохранится навсегда. Без этого после каждого деплоя придётся сканировать QR заново.

### Если у аккаунта включён облачный пароль

После сканирования страница попросит пароль (двухфакторную аутентификацию) — введи его прямо
на странице. Это единственный случай, когда что-то нужно набирать руками.

### Если QR-код не подходит к телефону

На странице входа есть второй вариант — «ввести код из Telegram»: вводишь номер в формате
`+380…`, Telegram присылает код сообщением от аккаунта «Telegram» (если других активных
устройств нет — придёт SMS), вводишь код на странице.

### Почему в Colab «не приходил код»

Telegram не отправляет код на почту или в SMS всегда: **если у аккаунта есть хотя бы один
активный сеанс в приложении, код приходит сообщением внутри Telegram** (от сервисного аккаунта
«Telegram», id 777000), а не SMS. Плюс две частые ловушки:

- в Colab поле ввода для номера/кода появляется **внутри вывода ячейки** — легко не заметить
  и подумать, что «ничего не приходит»;
- если запросить код несколько раз подряд, Telegram временно блокирует запросы
  (`FloodWait`) и код действительно перестаёт приходить — надо подождать, а не жать заново.

QR-вход этим проблемам не подвержен: ни кода, ни ожидания в ячейке — просто сканируешь.

## 1.3.2. Ошибка `ValueError: Not a valid string` — строка не в формате Telethon

**Симптом в логах Render:**

```
File ".../telethon/sessions/string.py", line 33, in __init__
    raise ValueError('Not a valid string')
ValueError: Not a valid string
ERROR:    Application startup failed. Exiting.
==> No open ports detected, continuing to scan...
```

**Что это значит.** В переменной `TG_SESSION` лежит строка, которую Telethon не может прочитать.
Telethon принимает только свой формат: **первый символ `1`**, дальше base64 примерно на 369
символов (внутри — dc_id, IP дата-центра, порт и 256-байтовый ключ авторизации).
Если строка пришла из стороннего «генератора сессий» (бот в Telegram, сайт, другая библиотека),
она почти наверняка в другом формате — например, длиной 362 символа и начинается с `A`.

Как проверить свою строку — два признака:

| Признак | Правильно | Как в присланной «не той» строке |
|---------|-----------|------------------------------|
| первый символ | `1` | `A` |
| длина | ≈ 369 символов | 362 символа |
| что внутри | 275 байт после декодирования | 271 байт |

**Исправление — любой из двух путей:**

1. **Войти через страницу входа (рекомендуется, строка не нужна вообще):** см. раздел 1.5.
   Сессия создаётся и сохраняется самим сервисом, копировать/вставлять ничего не надо.
2. **Сгенерировать правильную строку:** `python make_session.py` (или Colab из раздела 1.4) →
   строка начнётся с `1` → вставить в `TG_SESSION` **без кавычек и без пробелов**
   (Render иногда сохраняет значение с кавычками — сервис теперь сам их срезает, но лучше не вставлять).

**Что сделано в коде, чтобы это не повторялось:**

- сервис **больше не падает** при плохой строке: он выключает её, пишет причину в лог и в
  `/api/health`, и переходит в режим ожидания входа — сайт покажет ссылку на `/login`;
- перед созданием клиента строка **чистится** от кавычек, пробелов и переводов строк;
- строка **проверяется** заранее, и в ответе видно, что именно не так: «длина 271 байт вместо 275»,
  «первый байт версии 2 вместо 1», «Telethon-сессия всегда начинается с символа «1»»;
- если плохая строка в `TG_SESSION`, а в базе уже лежит рабочая сессия (её сохранила страница
  входа) — берётся рабочая.

## 1.4. Как получить TG_SESSION (три способа)

`TG_SESSION` — это «пропуск» сервиса в твой Telegram. Без него цифры не считаются,
но и только: на сам сайт это не влияет.

> ⚠️ **Сессия должна быть от обычного аккаунта** (вход по номеру телефона).
> Сессия бота не подходит — см. раздел 1.3.1.

### Способ 1. На компьютере (Windows/macOS/Linux)

1. Установи Python с <https://python.org> (на Windows при установке поставь галочку
   **Add python.exe to PATH**).
2. Открой терминал в папке `stats_service` (Windows: Shift + правый клик в папке →
   «Открыть в терминале» / PowerShell) и выполни:

   ```bash
   pip install telethon
   python make_session.py
   ```

3. Скрипт спросит: `API_ID`, `API_HASH` (с my.telegram.org), номер телефона
   **в международном формате** (`+380...`) и **код из Telegram** — он придёт в приложение
   Telegram (не по SMS, смотри чат «Telegram»). Если включён облачный пароль — попросит и его.
4. Скрипт напечатает длинную строку — это и есть `TG_SESSION`. Он же сохранит её рядом
   в файл `.env` (в git он не попадёт: он в `.gitignore`).

### Способ 2. Без установки Python — Google Colab (браузер)

1. Открыть <https://colab.research.google.com> → **New notebook**.
2. Вставить в ячейку и нажать ▶ (значения подставить свои):

   ```python
   !pip install -q telethon
   from telethon import TelegramClient
   from telethon.sessions import StringSession

   API_ID = 1234567            # ← свой api_id
   API_HASH = "свой_api_hash"  # ← свой api_hash

   with TelegramClient(StringSession(), API_ID, API_HASH) as client:
       print(client.session.save())
   ```

3. Появится поле ввода — номер телефона, затем код из Telegram.
4. Скопировать напечатанную строку — это `TG_SESSION`.

### Способ 3. GitHub Codespaces (браузер, бесплатный лимит)

Репозиторий на GitHub → кнопка **Code** → **Codespaces** → **Create codespace on main** →
в открывшемся терминале:

```bash
cd stats_service && pip install telethon && python make_session.py
```

### Куда вставить

Render → сервис статистики (`i-love-you-anya`) → **Environment** → **Add Environment Variable**:

| Key | Value |
|-----|-------|
| `API_ID` | число с my.telegram.org |
| `API_HASH` | строка с my.telegram.org |
| `TG_SESSION` | строка из способа 1/2/3 (или войти через `/login`, см. раздел 1.5) |
| `TARGET_PHONE` | `+380669543625` |
| `TARGET_NAME` | как подписывать её на сайте (например, `Аня`) |
| `MY_NAME` | `Я` |

Сохранить — Render сам перезапустит сервис. Затем открыть:

```
https://i-love-you-anya.onrender.com/api/health
```

Ждём `{"ok": true, "status": "ok", "total": ...}`. Первый ответ может занять минуту:
идёт пересчёт всей истории чата. Если появилось `FloodWait` — сервис подождёт и продолжит.

### Если с Telegram не получается совсем

Есть запасной путь без сервиса: выгрузить чат и получить файл `stats.json` для сайта.

1. Telegram Desktop → нужный чат → меню чата ⋮ → **Export chat history** → снять галочки с
   фото/видео → **Format: JSON** → экспорт.
2. В папке с выгрузкой (`result.json`) выполнить:

   ```bash
   cd stats_service
   python from_export.py путь/к/result.json --me "Я" --her "Аня"
   ```

   Скрипт напечатает цифры и положит `love_site/stats.json`.
3. Закоммитить `love_site/stats.json` — страница «Статистика» покажет цифры из выгрузки,
   даже когда сервис спит или не настроен. Живые цифры из сервиса имеют приоритет:
   как только Telegram заработает, страница покажет их.

## 2. Свой домен — как подключить

### Бесплатный домен

| Вариант | Плюсы | Нюансы |
|---------|-------|--------|
| **`.pp.ua`** (Украина) | реально бесплатно, обычный домен вида `dlya-tebya.pp.ua` | регистрация у аккредитованного регистратора (например, nic.ua), активация по SMS или через Telegram-бот `@ppuabot`; раз в год бесплатное продление |
| **`.is-a.dev`, `.thedev.id`, `.is-a.co`, `js.org`** | бесплатный поддомен вида `ty.is-a.dev` | регистрация через pull request на GitHub, для личных/некоммерческих проектов |
| **`eu.org`** | бесплатно навсегда | подтверждение заявки может занять недели-месяцы, отвечают не всем |
| поддомен хостинга | вообще ничего не делать | `*.onrender.com`, `*.pages.dev`, `*.github.io` — некрасиво, но бесплатно |

### Платный (если хочется коротко и красиво)

- `.com` — ~$8–12/год, `.me`/`.love`/`.family` — от ~$10–30/год.
- Самые честные цены по себестоимости: **Cloudflare Registrar**, дальше Namecheap / Porkbun.
- Бесплатный хостинг + платный домен = полностью рабочий вариант за ~10 $ в год.

### Как привязать домен к Render

1. Купить/зарегистрировать домен у регистратора.
2. Render → твой сайт → **Settings** → **Custom Domains** → **Add Custom Domain** → ввести домен.
3. Render покажет **точные DNS-записи** — скопировать их в DNS у регистратора:
   - для `www` и других поддоменов — обычно **CNAME** → `love-site-xxxx.onrender.com`;
   - для основного (апекс) домена — **A**/**ALIAS**-запись на адрес, который покажет Render
     (у Render это `216.24.57.1`; всё равно бери значение из панели).
4. Подождать 5–60 минут: Render сам выпустит HTTPS-сертификат (Let's Encrypt).
5. ⚠️ Если DNS домен обслуживает **Cloudflare** — переключи «облачко» на **DNS only** (серое),
   иначе Render не сможет выпустить сертификат.
6. Для `.pp.ua`: в панели nic.ua → раздел DNS/NS — либо прописать A/CNAME-записи Render,
   либо указать NS-серверы, если DNS ведёшь у Cloudflare.

## 3. Альтернативы Render (все бесплатные)

| Хостинг | Трафик | Свой домен | Особенности |
|---------|--------|-----------|-------------|
| **Cloudflare Pages** | **без лимита** (∞ requests, ∞ bandwidth) | да, до 100 доменов | лучший бесплатный вариант для статики; 500 сборок/мес; лимит 20 000 файлов и 25 МБ на файл |
| **GitHub Pages** | soft-лимит 100 ГБ/мес | да, бесплатный HTTPS | настройка в репо уже есть: `.github/workflows/pages.yml`; включить Settings → Pages → Source: **GitHub Actions**; адрес `https://darknesshefake-code.github.io/assets/` |
| **Netlify** | 100 ГБ/мес, 300 минут сборки | да | на новых аккаунтах — кредитная модель, лимиты ниже |
| **Vercel** | 100 ГБ/мес | да | бесплатный план — только для некоммерческих проектов |
| **Firebase Hosting** | 10 ГБ/мес | да | если уже в Google-стеке |

**Что бы я выбрал:** Render (уже настроен, симпатичный дашборд, домены на бесплатном плане) или
Cloudflare Pages, если планируешь много трафика и не хочешь думать про 100 ГБ.
Оба деплоятся из этого же репозитория — можно сначала попробовать один, потом сравнить.

### Cloudflare Pages за 4 шага (если решишь попробовать)

1. <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Выбрать репозиторий `assets`.
3. **Framework preset:** `None`, **Build command:** пусто, **Build output directory:** `love_site`.
4. **Save and Deploy**. Дальше каждый пуш в `main` = новый деплой.
