# stats_service — статистика переписки для сайта

Маленький сервис: считает сообщения в **одном** чате Telegram (по умолчанию
`+380669543625`) и отдаёт готовые цифры странице «Наша переписка в цифрах».

```
Telegram  ──►  Telethon (сессия аккаунта)  ──►  SQLite  ──►  GET /api/stats  ──►  сайт
               досчитывает только новые сообщения (по последнему id)
```

## Файлы

| Файл | Что делает |
|------|-----------|
| `app.py` | сам сервис: FastAPI + Telethon + SQLite, эндпоинты `/api/stats`, `/api/health` |
| `make_session.py` | один раз генерирует `TG_SESSION` (запускать на своём компьютере) |
| `from_export.py` | запасной путь: выгрузка Telegram Desktop → `love_site/stats.json` |
| `requirements.txt` | зависимости |
| `.env.example` | шаблон переменных для локального запуска |
| `.gitignore` | чтобы `.env` и база не попали в git |

## Эндпоинты

| Адрес | Ответ |
|-------|-------|
| `GET /api/stats` | `{status, chat, me{messages,percent}, other{...}, total, first_message_at, updated_at, progress}` |
| `GET /api/stats?refresh=1` | то же, но с принудительным обновлением |
| `GET /api/health` | `{ok, status, error, login_required, updated_at, total}` — для health check Render |
| `GET /login?secret=…` | страница входа в Telegram (QR-код или код из Telegram) |
| `POST /login/qr` | начать QR-вход |
| `GET /login/qr/status?secret=…` | состояние QR-входа (JSON, для автообновления страницы) |
| `POST /login/phone`, `POST /login/code`, `POST /login/password` | вход по номеру/коду/облачному паролю |

`status` бывает `ok` (всё посчитано), `syncing` (идёт пересчёт истории) или `error`
(не заданы ключи / неверная сессия) — в этом случае поле `error` объясняет причину.

## Вход в Telegram без консоли (QR-код в браузере)

1. В Render добавить переменную `LOGIN_SECRET` = любое секретное слово.
2. Открыть `<адрес сервиса>/login?secret=это_слово` → «Показать QR-код».
3. Телефон: Telegram → Настройки → Устройства → **Подключить устройство** → отсканировать.
4. Готово: сервис авторизован, страница покажет строку сессии.
   Строку можно положить в `TG_SESSION`, чтобы вход сохранился после пересборки сервиса.

Код подтверждения при этом не нужен. Если телефон не может сканировать — на той же странице
есть вход по номеру и коду из Telegram. Облачный пароль (2FA), если включён, страница спросит
после сканирования.

## Локальный запуск

```bash
cd stats_service
pip install -r requirements.txt
python make_session.py                  # создаст .env с TG_SESSION
uvicorn app:app --reload --port 8010
# проверка: http://localhost:8010/api/stats
```

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|-----------|--------------|-------|
| `API_ID`, `API_HASH` | — | ключи приложения с <https://my.telegram.org> |
| `TG_SESSION` | — | строка сессии из `make_session.py` |
| `TARGET_PHONE` | `+380669543625` | чей чат считаем |
| `TARGET_USERNAME` | — | необязательно: `@username` вместо номера |
| `TARGET_NAME` | имя из профиля | как подписывать её в ответе |
| `MY_NAME` | `Я` | как подписывать меня |
| `SYNC_INTERVAL` | `60` | как часто досчитывать, секунд |
| `ON_DEMAND_COOLDOWN` | `25` | не чаще, чем раз в N секунд обновлять по запросу сайта |
| `ALLOWED_ORIGINS` | `*` | источники для CORS (можно указать адрес сайта) |
| `DB_PATH` | `stats.db` | файл базы со счётчиками |
| `TRIGGER_WORD` | `инфо` | слово, на которое сервис отвечает статистикой в чате |
| `MAX_HISTORY` | `0` (вся история) | ограничить число сообщений при пересчёте |
| `DIALOG_SCAN_LIMIT` | `400` | сколько диалогов просматривать при поиске нужного чата |

## Как считается

- В зачёт идут и мои сообщения, и её; системные (без текста и без медиа) — пропускаются.
- Сообщения с фото/видео считаются.
- Первый запуск пересчитывает всю историю, дальше досчитываются только новые сообщения
  (`min_id = последний id`), поэтому цифра никогда не «прыгает» и не задваивается.
- Пересчёт идёт в фоне раз в `SYNC_INTERVAL` секунд и по запросу сайта (не чаще `ON_DEMAND_COOLDOWN`).

## ⚠️ Строка сессии должна быть в формате Telethon

Telethon принимает только свой формат: первый символ `1`, длина ≈ 369 символов
(275 байт после декодирования). Строки из сторонних «генераторов сессий» часто в другом
формате — на них Telethon отвечает `ValueError: Not a valid string`.

Сервис теперь проверяет строку заранее и **не падает**: он пишет причину («длина 271 байт
вместо 275», «первый байт версии 2 вместо 1») в лог и в `/api/health`, и ждёт вход через
`/login`. Если в базе уже сохранена рабочая сессия — используется она, а bad-строка игнорируется.

## ⚠️ Сессия бота не подходит

`TG_SESSION` должен принадлежать **обычному аккаунту** (вход по номеру телефона),
а не боту. Telegram запрещает ботам читать историю чатов и список диалогов:

```
BotMethodInvalidError: The API access for bot users is restricted
(caused by GetDialogsRequest / GetHistoryRequest)
```

Сервис проверяет это при старте: если вошёл бот, в логе и в поле `error` у `/api/stats`
будет прямое объяснение, а сайт покажет его на странице «Статистика».
Проверить свою строку: `python make_session.py --check "строка"`.

## Триггер в Telegram

Напиши в отслеживаемом чате слово `инфо` — сервис досчитает новые сообщения и заменит
это сообщение статистикой (то же поведение, что в исходном скрипте). Слово настраивается
переменной `TRIGGER_WORD`.

## Запасной путь без Telegram API

Если сессия недоступна, цифры можно взять из выгрузки чата:

```bash
# Telegram Desktop → чат → ⋮ → Export chat history → Format: JSON → result.json
python from_export.py ~/Downloads/ChatExport/result.json --me "Я" --her "Аня"
```

Скрипт создаст `love_site/stats.json` с тем же набором полей, что отдаёт `/api/stats`.
Страница «Статистика» использует файл, когда API недоступен или ещё не настроен.

## Безопасность

`API_ID` + `API_HASH` + `TG_SESSION` = полный доступ к аккаунту Telegram.
Держи их только в переменных окружения Render. Если строка утекла — Telegram →
Настройки → Устройства → завершить сеанс, затем сгенерируй новую сессию.
Сервис читает переписку и ничего не отправляет: только `iter_messages` и `iter_dialogs`.
